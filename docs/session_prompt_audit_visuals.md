# AUDIT PROMPT 2 — Visuals & Art Direction: Fix or Rebuild the 3D Look of "Steel Tycoon"

Same project as before (**https://github.com/leeblaab/steel-tycoon** — public during the audit window). The first audit covered architecture; this one is about one thing only: **the game currently looks bad and communicates nothing visually.** Be blunt and concrete. The domain SME (16 yrs steel mills) can judge "does this look like a real plant"; you judge "does this look like a good game" — both matter, fun first.

## Current visual state (verify in repo)
- Art anchor: Kenney CC0 low-poly props + GLBs generated by an image-to-3D model (ComfyUI). Known defect: every ~1.6 MB ComfyUI GLB is quantization-corrupt; one manual rebuild-from-pristine verified. Pristine source GLBs (425 MB, 70–80 MB each) live outside the repo.
- The fullplant diorama (`web/src/ports/slice*/browser/assets/`, ~60 MB of GLBs in-repo): a top-down/isometric-ish factory where equipment is hard to tell apart, material flow is invisible, and nothing teaches the player what a DRI-EAF plant actually looks like or how stuff moves through it. The SME's blunt verdict: "it really sucks and presents nothing."
- Rendering today: React Three Fiber, plain materials, static lighting, no post-processing that we know of; desktop web only.
- What works conceptually: the zone layout mirrors a real plant flow (jetty → yards → DRI → EAF → LF → Caster → Rolling → Dispatch), and per-node GLB reveal + tap-to-inspect info-cards are already wired.

## Hard constraints
- Solo SME + AI agents, no in-house 3D artist, small budget. Mobile target eventually (memory/draw-call budgets apply).
- Style must stay readable as an industrial plant — learning layer is a core feature, not decoration.
- Any recommendation must decompose into micro-steps an AI agent can execute (Blender Python scripting, gltf-transform pipelines, shader/material code are all fair game — no human artist assumed).

## Part A — The models themselves
1. **Honest verdict on the ComfyUI image-to-3D pipeline.** Salvageable with post-processing (decimation, retopo, re-quantization fixes in Blender/Python), or dead end? What specifically goes wrong and can a scripted repair pass fix it?
2. **From-scratch options ranked for a no-artist team**, with honest effort/quality estimates per option:
   - Kenney CC0 + kitbashing/assembling in Blender via Python scripts
   - Other free/CC0 packs (which ones fit industrial/steel specifically — e.g. any port, rail, crane, conveyor, factory packs you know of)
   - Quixel/BlenderKit/Poly Haven-style sources — licensing for a commercial mobile game?
   - AI-generated: current state of text-to-3D / image-to-3D tools (Treillis/Meshy/Tripo/Hunyuan3D etc.) — which produce game-usable clean topology vs. ComfyUI-quality soup?
   - Simple procedural/box-modeled equipment (the "factorio-flat-3D" style: readable silhouettes, custom colors per material stream) — is THIS actually the right answer for a learning-focused plant sim?
3. **What should each piece of equipment's silhouette communicate** to someone who has never seen a mill (EAF vs LF vs Caster vs rolling mill must be distinguishable at a glance from above)? Give a concrete visual language: shape cues, color coding per material stream (scrap/DRI/hot metal/slag/finished), scale relationships.
4. **Sample deliverables you can produce right now in this chat**: pick ONE flagship asset (the EAF, or the fullplant layout) and draft either (a) a Blender-Python script that procedurally builds a clean, stylized, game-ready version with proper materials and <2 MB GLB output, or (b) a precise art-direction spec an agent could feed to an image/3D generator + repair pipeline. Choose whichever you think has the better odds; produce it inline.

## Part B — Scene & presentation (why "presents nothing")
5. **Camera & framing for a 5-zone diorama**: fixed isometric vs. free orbit vs. guided camera per quest step? What makes plant flow legible on a phone screen?
6. **Material-flow visualization**: how do tycoon/factory games (Factorio, Shapez, Workers Resources, Good Company, Industrialist) make product movement readable? Concrete techniques for us: animated conveyor meshes, colored particles along splines, ship/truck/tank-car sprites, fill-level rings on stockyards — cheapest-first ranking.
7. **Lighting/mood for an industrial scene** at low cost: baked vs. real-time, day/night worth it?, emissive glow on hot metal (tap-to-stream color), fog/DOF budget on mobile.
8. **Feedback & juice**: what visual/audio feedback should a placement, a completed heat, a shipped bundle trigger? Ranked by effort-to-impact for our stack.

## Part C — The whole thing: ideas & improvement passes
9. Given the architecture you already audited (hub tickloop, quest chain, info-cards): **what 3 visual/UX upgrades would most increase both fun AND learning** per unit of effort? Rank top 5.
10. **The learning layer's presentation**: cards are text-heavy today. Ideas to make the plant itself teach (guided camera callouts, animated process cutaways — e.g. see inside the EAF during a heat, DRI shaft cross-section), ranked by feasibility for our team.
11. **Anything else you'd change if you owned this project for one month** with only AI agents as hands: kill features, add features, re-scope visuals entirely — opinionated, no hedging.
