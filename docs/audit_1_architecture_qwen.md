## 3. Answers to your nine questions

### Q1 — Retiring the four `sim.ts` forks
**Your premise is half-wrong in the best way: the strangler already happened at the engine level.** The game path is `fullplant → session.ts → hub/catalog.ts → shared parity ports` (`catalog.ts:5–8`); the browser forks power only the legacy per-slice demo scenes. So this is not "port 1,600 lines" — the ports exist and are tested (slice3/4/5 parity: 15/18/15 cases). The remaining work is **scene-level**: the 25.10 contract (roadmap:1364) makes slice scenes drill-ins, and a drill-in must render the *home's live state*, never an independent fork.

**Opinion: strangler per scene, never big-bang, order S3 → S4 → S5, S1's 5.5 KB replay last.** Per slice, four gated micro-steps: (a) write a view-model adapter from port state to the scene's existing props (the `port_adapters.ts` projection pattern already exists); (b) flip the scene's data source behind one flag; (c) verify with the frozen fixture log + a Playwright tap probe; (d) **delete `sim.ts` in the same phase** — no permanent dual paths. S2's timeline scene stays until its real port lands (it's the only S2 visual). Trade-off named: you keep a temporary adapter layer per slice (~50–100 lines each) instead of a risky rewrite; the adapters die when drill-ins are rebuilt on home state. **Never port the forks' internals or write tests against them — the fixtures are the contract.**

### Q2 — One authoritative plant-state
**Opinion: a single plain `PlantState` object + the existing registry grown by exactly three primitives. No ECS.** You have ~25 machines; an ECS buys nothing and violates §17.4.

Shape: `{ tick, speed, onboard, slices: {id → {state, unlocked}}, registry, quests, events, decisions }`. Tick order fixed and topological along material flow (s1→s2→s3→s4→s5). Per tick: apply inbound transfers committed last tick → step each live slice (pure) → validate+commit transfer requests → assert ledgers. **Two-phase handoffs**: material debits source into an explicit `in_transit` ledger with `arrival_tick` (even if transit = 1 tick), credits destination on arrival — never same-tick teleport unless the mirror already does. **One physical stockpile = one inventory id** (S1 yard shared with S2 reclaim is the *same* id; charge-bucket→EAF is a transfer with reservation). Reservations stay inside the owning slice's mirror rules (S2 charge reservations); the registry only exposes `reserve/release/consume` with owner tags so no cross-slice double-spend. Add the plant-wide identity: external inputs = outputs + losses + Δinventory. The 25.10 clause (2) "zone-boundary buffers absorb output while downstream isn't live" (roadmap:1365) is your designed absorption mechanism — implement those buffers as **real inventories**, not fudge factors. Save/load stays trivial because every slice state is already JSON-plain; enforce it with a `JSON.parse(JSON.stringify(state))` round-trip test. **Defer full five-loop lockstep complexity until the first boundary (S1-yard→S3-DRP, i.e. the Ore Belt) proves the pattern** — that's literally your next onboarding step, so gameplay and architecture converge for free.

### Q3 — Save/load strategy
**Opinion: full-state serialize, not snapshot+replay — and the architecture already chose it** (`tickloop.ts:77–81` resume; RNG word in state; `save_load.ts` v1). Replay would require an input-log subsystem, O(campaign-length) loads, and — the killer — *silent* breakage of old saves whenever a rule tweaks. Full-state snapshots fail *loudly* via version checks, which is the approved behavior.

Versioning discipline for a churning shape: integer `save_version`, bump on **every** shape change (no ceremony); one pure migration function per step, chained vN→vN+1, each tested against a frozen example save (`tests/fixtures/saves/vN.json`, a few KB each). **During V3 pre-release, bump-and-discard with a loud message + export prompt is honest and cheap**; mandatory migrations only start at first external release. The real gap is B2: schema v1 was hub-shaped and the home doesn't use it. v2 must add `onboard{index,built,clockRunning}`, per-slice `{state,unlocked}`, `decisions`, `speed` — exactly contract clause (10) (roadmap:1373), which also mandates autosave + level-checkpoint slots. Wire that before adding any multi-slot UI.

### Q4 — Web → mobile
**Opinion: packaging stays GAME phase 2 (settled, and correct per the priority order). Adopt a mobile-ready *contract* today, as a checklist, not a workstream.** Cheap-now decisions that prevent an expensive migration: pointer-only input with ≥44 px targets and no hover-carried meaning (clause 6 already mandates large hit targets — enforce it in review); keep all state UI in DOM overlay (already the pattern — this is exactly what Capacitor wraps well); touch-ready camera gestures (OrbitControls-class, no mouse-only custom code); and **perf budgets as gates from today**: ≤150 draw calls, ≤200k visible tris, ≤256 MB GPU textures, ≤60 MB total download, 30 fps floor on a mid-tier phone. Kill the 100 ms full-tree re-render (`main.tsx:228`) before it fossilizes. When packaging time comes: **Capacitor** (WebView preserves localStorage semantics; add a filesystem plugin for export); PWA is a cheap optional add later, but iOS storage eviction makes export/import the real save safety net. The most expensive mobile decision happening *right now* is the 21 MB float GLBs — fix that in the asset recipe (Q5), not at packaging time.

### Q5 — GLB pipeline
**Opinion: salvageable — but the current recipe is a workaround that trades corruption for bloat, and must gain one stage before it's a shipping pipeline.** The defect is the ComfyUI exporter's quantization, not quantization itself; "never accept KHR_mesh_quantization" (step4 doc:39–40) dequantizes to float and inflates 1.6 MB → 21 MB (13×). Two 21 MB assets are 71% of your GLB bytes and would dominate a mobile download.

Shipping recipe (one new stage, keeps your verified rebuild): pristine → float rebuild (existing recipe) → **gltf-transform/gltfpack optimize** (weld/dedup/prune + meshopt or Draco at known-good precision) → **gltf-validator clean** → render smoke → **≤2 MB gate** → commit + manifest entry (hash, source, license, recipe). Prove it on the *next* rebuild (DRP, needed for step 4) before touching the other seven — that respects your one-asset-per-approval rule and fixes the pipeline once. ComfyUI's honest role: concept art and 2D card illustrations (corruption-proof, where it's strong); meshes only through the fixed post-process. Kenney CC0 + procedural primitives remain the agreed split (roadmap §9.1) — don't relitigate it. Dedupe `eaf.glb` ×2 and slice2's `assets/`/`public/assets/` ×7 (~5 MB free). Pristine 425 MB: **never in git** — external backup + in-repo hash manifest; that's a one-hour bus-factor fix. Both existing scripts are Godot-era (`asset_pipeline.py` resizes 2D icons; `assemble_node_glbs.py` bakes vertex colors for Godot) — replace with one `scripts/optimize_glb.py`. Budgets as Q4; for the 5-zone diorama, merge static geometry per zone and instance repeats (conveyors, billets) — that's where your draw calls go.
